## Контекст

Наша команда разрабатывает «Учёт заявок на ремонт оборудования» (repair-requests) — сервис, в котором сотрудники подают заявки на ремонт, а инженеры АХО принимают и закрывают их, — в рамках курса "Управление конфигурацией бизнес-приложений".

**Характеристики проекта:**
- Размер команды: 3 человека
- Длительность проекта: 16 недель (1 семестр)
- Частота релизов: промежуточные демо на каждой практике (раз в 2 недели) + финальный релиз
- Опыт команды с менеджерами зависимостей: все трое — pip и `venv`; Poetry Мария пробовала в личном проекте; uv никто не использовал. Сейчас проект управляет зависимостями через `requirements.txt`, полученный `pip freeze`
- Требования к воспроизводимости окружения: у всех участников, в Docker-образе и у проверяющих команд — одни и те же версии пакетов и Python (3.14, из README)

**Проблема:** текущий `requirements.txt` из `pip freeze`:
1. Смешивает прямые зависимости (`fastapi`, `uvicorn[standard]`) с транзитивными (19 строк вместо 2) — непонятно, что можно удалить и что обновлять
2. Не фиксирует версию Python — у Ивана и Олега разные версии
3. Не разделяет основные и dev-зависимости (тесты и линтеры появятся в модуле 3)
4. Не содержит хешей — нет гарантии, что установился тот же пакет

## Рассмотренные варианты

| Критерий | A: pip + `requirements.txt` | B: Poetry | C: uv |
|---|---|---|---|
| Lock-файл: прямые и транзитивные раздельно, хеши | Нет: один плоский список, хешей нет | Да: `pyproject.toml` + `poetry.lock` с хешами | Да: `pyproject.toml` + `uv.lock` с хешами |
| Фиксация версии Python | Нет | `requires-python` в `pyproject.toml`, сам Python не ставит | `requires-python` + `.python-version` (`uv python pin`), может скачать нужный Python |
| Основные и dev-зависимости | Только разными файлами вручную | Группы (`--group dev`) | `--dev` / dependency groups |
| Установка строго по lock-файлу | Нет | `poetry install` + `poetry check --lock` | `uv sync --locked` (ошибка при рассинхроне) |
| Скорость установки | Средняя | Медленнее всех | Быстрее всех (по документации и пробе) |
| Как ставится в Docker-образ (гипотеза) | `pip install -r requirements.txt` | `pip install poetry` или `poetry export` в `requirements.txt` | `pip install uv`, затем `uv sync --locked` |
| Стоимость перехода | Нулевая | Средняя: `pyproject.toml`, плагин экспорта | Низкая: `uv init`, `uv add` |
| Зрелость, документация | Стандарт | Зрелый, много статей | Молодой, но документация подробная |
| Опыт команды | Есть у всех | У одного | Нет |

### Вариант A: pip + `requirements.txt`
**Суть:** оставить `requirements.txt` из `pip freeze` и `venv`, как на практиках №1–2.  
**Плюсы:**
- Ничего не надо осваивать
- Встроен в Python

**Минусы:**
- Нет `pyproject.toml` и lock-файла — результат недели 6 курса не достигается
- Транзитивные зависимости перемешаны с прямыми, версия Python не фиксируется

**Подходит ли нам:** Нет — не даёт lock-файла и воспроизводимости.

### Вариант B: Poetry
**Суть:** `pyproject.toml` с прямыми зависимостями и `poetry.lock`; Poetry ставится через pipx.  
**Плюсы:**
- Зрелый инструмент, много документации
- Группы зависимостей, проверка `poetry check --lock`

**Минусы:**
- Для образа нужен плагин `poetry-plugin-export` и шаг экспорта, который легко забыть
- Медленнее uv, Python не ставит

**Подходит ли нам:** С оговорками — рабочий вариант, но лишний шаг экспорта для Docker.

### Вариант C: uv
**Суть:** `pyproject.toml` + `uv.lock` + `.python-version`; uv ставится установщиком и одной командой синхронизирует окружение по lock-файлу.  
**Плюсы:**
- `uv sync --locked` проверяет lock-файл и ставит окружение одной командой — та же команда годится для Dockerfile
- Фиксирует версию Python через `.python-version`, быстро ставит пакеты

**Минусы:**
- Никто в команде с ним не работал
- Молодой инструмент, интерфейс ещё меняется

**Подходит ли нам:** Да.

## Решение

Мы выбрали **uv**.

**Как ставятся зависимости** (проверено на практике №3):

```
Разработчик:  uv sync                  # окружение .venv по uv.lock
              uv run uvicorn main:app --reload
Dockerfile:   COPY --from=ghcr.io/astral-sh/uv:0.13.0 /uv /bin/uv
              COPY pyproject.toml uv.lock ./
              RUN uv sync --locked --no-dev --no-install-project
```

**Правила работы с зависимостями:**
1. Коммитятся `pyproject.toml`, `uv.lock` и `.python-version`; `.venv/` — в `.gitignore`
2. Зависимость добавляется только командой `uv add <пакет>`, удаляется `uv remove <пакет>`; `pyproject.toml` и `uv.lock` правятся в одном коммите
3. Dev-зависимости (тесты, линтеры) — `uv add --dev <пакет>`, в образ не попадают
4. В `pyproject.toml` только прямые зависимости; транзитивные — только в `uv.lock`
5. `requirements.txt` после перехода удаляется — один источник правды

## Обоснование решения

**Почему мы выбрали именно этот инструмент?**

1. **Воспроизводимость:**
   `uv.lock` с хешами и `.python-version` дают одинаковое окружение у всех и в образе; `--locked` не даёт собрать образ из устаревшего lock-файла.

2. **Одна команда для разработчика и для Docker:**
   `uv sync` локально и `uv sync --locked --no-dev` в образе — без шага экспорта, который нужен Poetry.

3. **Стоимость перехода:**
   Проект маленький, две прямые зависимости: `uv init` и `uv add` — несколько минут.

4. **Требования DoD курса:**
   `pyproject.toml` и lock-файл в репозитории, стек воспроизводим по README.

## Последствия

### Положительные (+)
- Прямые зависимости видны в `pyproject.toml`, транзитивные — в `uv.lock`
- Версия Python зафиксирована в `.python-version`
- Установка зависимостей быстрее, чем pip
- Практика №3: первая сборка образа — 16 с (слой `uv sync` уже был в кэше Docker), повторная после правки `main.py` — 11 с, шаги `COPY pyproject.toml uv.lock` и `RUN uv sync` — `CACHED`
- Версии пакетов в `uv.lock` совпали с прежним `requirements.txt`; добавлен драйвер `psycopg[binary]` 3.3.6

### Отрицательные (-)
- Каждому участнику нужно поставить uv установщиком вне `venv/`
- Старые инструкции с `pip install -r requirements.txt` перестанут работать — README нужно обновить
- Сверх ожиданий: `.python-version` (`uv python pin 3.14`) и бинарник uv из образа `ghcr.io/astral-sh/uv` с той же версией, что у разработчиков (0.13.0); при обновлении uv тег в `Dockerfile` меняется вручную

### Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Гипотеза для Dockerfile не сработает | Средняя | Среднее | Сработал: вместо `pip install uv` — бинарник из `ghcr.io/astral-sh/uv:0.13.0`, установка `uv sync --locked --no-dev --no-install-project`; закрыт PR практики №3 |
| `uv.lock` разойдётся с `pyproject.toml` | Средняя | Высокое | `uv sync --locked` в Dockerfile падает при рассинхроне; правило 2 |
| Участник запустит приложение из старого `venv/` | Средняя | Низкое | `deactivate`, запуск через `uv run`; описать в README |
