## Контекст

Наша команда разрабатывает «Учёт заявок на ремонт оборудования» (repair-requests) — сервис, в котором сотрудники подают заявки на ремонт, а инженеры АХО принимают и закрывают их, — в рамках курса "Управление конфигурацией бизнес-приложений".

**Характеристики проекта:**
- Размер команды: 4 человека (Анна Волкова — с 2026-10-13)
- Длительность проекта: 16 недель (1 семестр)
- Частота релизов: промежуточные демо на каждой практике (раз в 2 недели) + финальный релиз
- Опыт команды с переменными окружения, `.env`, pydantic: `os.environ` и `.env` — с практики №3 у всех; pydantic — модели запросов FastAPI видели все, `pydantic-settings` никто не использовал; python-dotenv Мария подключала в личном проекте
- Окружения проекта: `dev` — ноутбуки участников (Windows, macOS, Linux), стек в Docker Compose (`compose.yaml`) или приложение без Docker через `uv run`; `prod` — сервер в модуле 4 (пока гипотеза). Секреты `prod` знает только владелец репозитория (Иван) и тот, кто будет разворачивать

**Проблема:** конфигурация сейчас читается одной строкой `os.environ.get("DATABASE_URL")` прямо в `/health`; об отсутствии переменной приложение узнаёт только при запросе; остальные параметры зашиты в код. Нужно выбрать механизм конфигурации, способ различать `dev` и `prod` и защиту от попадания секретов в git (DoD, раздел 2).

**Аудит по 12-Factor** (ветка `main`, коммит `3ae3870`, 2026-10-13):
